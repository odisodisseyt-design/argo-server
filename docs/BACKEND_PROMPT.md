## Контекст
Русская текстовая RPG, свободный ввод вместо меню. Сервер — единственный источник правды, приложение — оболочка. Игрок не должен видеть логи, промты, ID, reason_code, стектрейсы, margin. Модель предлагает, код решает, модель озвучивает. Смерть постоянная, без HP/урона/критов (части тела и описательные состояния). Есть эпохи E0–E5, 129 классов, живой мир (время, погода, NPC с расписаниями и памятью, фракции, экология), пошаговый кооп: один приказ на игрока, реакция после сдачи всеми, случайный первый.

## Стек
FastAPI + uvicorn (один воркер), aiosqlite / SQLite WAL, argon2-cffi, httpx, Ollama на 127.0.0.1:11435. systemd `text-world`, Caddy. Схема: `server/db.py`, миграции — `server/migrations.py` (свой раннер, SQL написан в стиле будущих Alembic-операций; PostgreSQL сейчас нет). Версия сервера 0.0.8.

## Как устроен ход
`POST /api/turn` → `main.turn` → `engine.submit_order`:
1. Принимает `text` (старый клиент) или `command` (новый). Лимит 1000 символов → 422.
2. `Idempotency-Key` (заголовок): повтор возвращает сохранённый ответ без эффектов; TTL 24 ч; ключ привязан к (campaign_id,user_id); при несовпадении 409; ошибки не кэшируются. Флаг `TW_REQUIRE_IDEMPOTENCY` сейчас 0.
3. `limits.check_turn_rate`: 30 приказов/мин и 200/час на игрока → 429 + Retry-After.
4. `engine.parse_intent`: сначала детерминированный разбор по глаголам из `actions.json`; если не сработал — LLM intent с таймаутом 5 с; пустой ответ/таймаут → повтор детерминированного разбора (`allow_ambiguous=True`), затем уточняющий вопрос. Ответ валидируется: action_id только из пака, target только из ближайших.
5. `resolver.preview` считает шанс без броска.
6. Под `locks.campaign_lock` (fcntl.flock на файл кампании, кросспроцессный, снимается при падении) в одной транзакции: `orders`, `pending_json`, `turn_idempotency`. Занят → 409 + retry_after. Если сдали все — после освобождения лока вызывается `_resolve_step`.
7. `_resolve_step` снова берёт лок: `resolver.resolve` считает margin = capability − requirement; RNG только при разнице ±1 и детерминирован по seed `campaign:step:user:action:raw_text`; `_apply_effects` применяет только эффекты из пака; `worldsim` тикает мир; нарратор получает только факты и список ALLOWED; наррации для всех игроков идут параллельно (`asyncio.gather`), таймаут 8 с, пустой ответ → фактическая строка. Весь шаг коммитится одной транзакцией. Запись в `steps` и `ledger`, рассылка `turn_final` по WS. Почему не «двухфазный лок»: при падении во время прозы можно было бы дважды применить эффекты; выбран один атомарный шаг.

## Память и защита от выдумок
Память — не контекст модели, а БД: `campaigns.state_json` (мир, NPC, флаги, журнал), `campaign_members.character_json`, `ledger`, `steps`, `orders`. Модели не передаётся история переписки — каждый ход ей даётся свежий срез фактов. Слои: белый список каталога (`catalog.py`), гейты эпох/условий (`gates.py`), валидация action/target, валидатор пака (`packs.py`), DTO-белый список (`dto.py`), промт нарратора с запретом придумывать объекты. `llm_logs` пишет промт, ответ, модель, задержку, ошибку; добавлена колонка `model_version`.

## Модели (новое)
`server/models.json` — каталог: `{id,title,strength 1..5,speed 1..5,cost,recommended_for,provider,intent_model,narrator_model,timeouts}`. `GET /api/models` отдаёт только публичные поля (никаких ключей, провайдеров, имён моделей). По умолчанию `fast` = `tw-qwen35-08b` и для intent, и для narrator (самая быстрая для проверки); `balanced` = 0.8b intent + 2b narrator. Модель одна на кампанию, меняет основатель через `POST /api/campaign/{id}/model` только между шагами. Ключи API — только в env сервера. Недоступная модель помечается `available:false`.
